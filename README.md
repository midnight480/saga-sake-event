# 佐賀 蔵めぐり

佐賀の酒蔵が集まる**合同試飲イベント**の、受付・在庫・チケットを 1 つにまとめた
Web サービスです。

**主催者・酒蔵・参加者の 3 者が、同じ画面の情報を共有します。**
どこか 1 台で操作すると、ほかの画面が数秒で追いつきます。

- 参加者は**ブースの前でスマホから注文**し、できあがりを画面で知る
- 酒蔵は**持ち込んだ酒を自分で登録**し、注文を順に片付ける
- 主催者は**在庫・混雑・遅延をひと目で把握**し、券が切れたらその場で増やす

アプリのインストールは要りません。**URL を開くだけ**で、iPhone でも Android でも
同じように使えます。

## 主催者の方へ ─ 公開するまで

**プログラミングの知識は要りません。** かかる時間はおよそ **15 分**、費用は
**無料の範囲で始められます**。

入口が 2 つあります。**ほとんどの方は A です。**

### A. このリポジトリを配布された方（通常はこちら）

主催を引き受けて、URL や案内を受け取った方はこちらです。
リポジトリを自分のアカウントに複製してから公開します。

[![Vercel でデプロイ](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fmidnight480%2Fsaga-sake-event&project-name=saga-sake-event&repository-name=saga-sake-event&env=ORGANIZER_EMAILS,BREWERY_GUEST_INVITE_CODE&envDescription=%E4%B8%BB%E5%82%AC%E8%80%85%E3%81%AE%E3%83%A1%E3%83%BC%E3%83%AB%E3%82%A2%E3%83%89%E3%83%AC%E3%82%B9%EF%BC%88%E5%BF%85%E9%A0%88%EF%BC%89%E3%81%A8%E3%80%81%E9%85%92%E8%94%B5%E7%89%B9%E5%88%A5%E6%9E%A0%E3%81%AE%E6%8B%9B%E5%BE%85%E3%82%B3%E3%83%BC%E3%83%89%EF%BC%88%E4%BB%BB%E6%84%8F%EF%BC%89&envLink=https%3A%2F%2Fgithub.com%2Fmidnight480%2Fsaga-sake-event%2Fblob%2Fmain%2Fdocs%2F%25E3%2583%2587%25E3%2583%2597%25E3%2583%25AD%25E3%2582%25A4%25E6%2589%258B%25E9%25A0%2586.md)

1. 上のボタンを押す
2. GitHub でログイン（無料。持っていなければその場で作れます）
3. **「Repository Name」に、あなたのイベントの名前を入れる**（下記参照）
4. **「Create」** を押す
5. 次の画面で、下の表のとおりになっているか確かめてから **「Deploy」**

#### ⭐ 名前の付け方 ─ ここで入れた名前が、そのまま URL になります

```
Repository Name に  kuramenguri-saga-2026  と入れると
       ↓
https://kuramenguri-saga-2026.vercel.app  が自分のサイトの URL になります
```

短い URL は**世界中で早い者勝ち**です。`saga-sake-event` のまま進めると、
すでに誰かが使っていた場合、この短い URL はもらえません
（アカウント名入りの長い URL は必ずもらえるので、公開はできます）。

**地域名や年を入れて、自分だけの名前にしてください。**

| | 例 |
| --- | --- |
| ◎ おすすめ | `kuramenguri-saga-2026` / `saga-sake-2026aki` / `sagakura-spring` |
| △ 被りやすい | `saga-sake-event`（初期値のまま） / `sake-event` / `kuramenguri` |

使える文字は **小文字の英数字とハイフン（-）** です。日本語は使えません。

> あとから変えることもできます（Vercel の **Settings → General → Project Name**）。
> ただし**変えると前の URL は使えなくなる**ので、案内を配る前に決めてください。

### B. このリポジトリを自分で持っている方

`midnight480/saga-sake-event` の所有者・共同編集者、または動作確認のために
自分のアカウントで試す方はこちらです。

**A の Deploy ボタンは使えません。** あのボタンは「リポジトリを自分のアカウントに
複製する」ためのもので、すでに同じ名前のリポジトリがあると
`A repository named "saga-sake-event" already exists.` で止まります。
ここで名前を変えて進めると**別のコピー**ができ、元のリポジトリを更新しても
サイトに反映されなくなります。

1. **<https://vercel.com/new>** を開く
2. 「Import Git Repository」の一覧から **`saga-sake-event`** を選び **「Import」**
   - 一覧に出ないときは検索欄に `saga-sake` と入力
   - それでも出ないときは一覧の下の **「Adjust GitHub App Permissions」** から
     `saga-sake-event` へのアクセスを許可する
3. 次の画面で、下の表のとおりになっているか**必ず確かめてから** **「Deploy」**

---

### ⚠️ Deploy を押す前に、この 3 つを確認してください

似た名前のリポジトリがあると、**違うプロジェクトを公開してしまいます。**
Vercel の画面で、次の 3 か所が合っているか見てください。

| 画面の項目 | 正しい値 | 違っていたら |
| --- | --- | --- |
| **Repository** | `midnight480/saga-sake-event` | 別のリポジトリです。戻ってやり直してください |
| **Git Branch** | `main` | `main` 以外を選ぶと、未完成の内容が公開されます |
| **Application Preset** | `Next.js` | `Other` と出ていたら、**違うリポジトリを見ています** |

> **Application Preset がいちばん分かりやすい目印です。**
> 正しいリポジトリなら Vercel が自動で `Next.js` を検出します。
> `Other` のままなら、リポジトリ名を読み違えていないか確かめてください
> （例: `saga-event-space` は別のプロジェクトです）。

### Environment Variables ─ 2 つだけ入れてください

`Environment Variables` を開くと 5 つの欄が出ます。**うち 2 つだけ入力します。**

| 欄 | どうするか |
| --- | --- |
| **`ORGANIZER_EMAILS`** | **ご自身のメールアドレスを入れる**（下記参照） |
| **`BREWERY_GUEST_INVITE_CODE`** | 「酒蔵特別枠」を使うなら好きな合言葉を入れる（使わないなら空） |
| `DATABASE_URL` | **空のまま**（あとで Neon が自動で入れます） |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | **空のまま**（あとで Clerk が自動で入れます） |
| `CLERK_SECRET_KEY` | **空のまま**（同上） |

> #### なぜ `ORGANIZER_EMAILS` を先に入れるのか
>
> 入れないと「**最初にログインした人**」が自動で主催者になります。
> URL を先に誰かに開かれると、その人が運営権限を持ってしまいます。
>
> ここで入れておけば、**そのメールアドレスの人だけが主催者**になります。
> 複数指定するときはカンマ区切りです（`a@example.com,b@example.com`）。
>
> あとから Settings → Environment Variables で追加することもできますが、
> その場合は再デプロイが必要になります。

空のままにした 3 つは作られません。このアプリは未設定でも公開でき、
開くと「はじめの設定」画面が足りないものを案内します。

**6 番の設定も、Vercel の画面でボタンを押すだけです。**

### 公開される URL について

Vercel は次の 2 つの URL を用意します。

```
https://saga-sake-event.vercel.app          ← 空いていれば付く（短い形）
https://saga-sake-event-〇〇〇.vercel.app    ← アカウント名入り。必ず使える
```

短いほうは世界中で早い者勝ちです。すでに誰かが使っていると付きませんが、
**アカウント名入りの URL は必ず使えます**。画面に表示された URL を
そのまま配ってください。

アカウント名が入るぶん、**ほかの主催者が同じ時期に公開しても衝突しません。**
複数のイベントを並行して運営できます。

自前のドメインを使いたい場合は、Vercel の **Settings → Domains** から
割り当てられます。

### 公開したあとの自動更新

Vercel は **`main` ブランチ**を見ています。`main` に push するたび、
本番サイトが自動で作り直されます（1〜2 分）。

ほかのブランチに push した場合は、本番とは別の「確認用 URL」が作られます。
本番は変わりません。

### 公開したあと、最初にやること

1. **自分でログインする。** 最初にログインした人が主催者になります。
   ほかの人に先に開かれないよう、URL を配る前に済ませてください。
2. **イベント設定**で日付と時刻を入れる
3. **蔵アカウント**で出展する酒蔵を登録し、印刷して各蔵に渡す
4. **チケットQR**で当日券を発行し、印刷して受付に置く

## かかる費用

| | 無料の範囲 | 超えたら |
| --- | --- | --- |
| Vercel（サイトの置き場所） | 個人利用は無料 | 規模が大きくなったら有料プラン |
| Neon（データの保存） | 無料プランで十分 | 数百人規模のイベントなら無料枠で足ります |
| Clerk（ログイン） | 月 10,000 人まで無料 | 来場者がそれ以上なら有料 |

一般的な規模（来場者 数百人・出展 30 蔵）なら、**すべて無料枠に収まります**。

ただし **Clerk は独自ドメインを設定するまで「開発モード」** で動き、その間は
**登録できる人数が合計 100 人まで**に制限されます。100 人を超えるイベントでは
[独自ドメインで本番運用する](docs/独自ドメインで本番運用する.md) をイベント前に
済ませてください（すでにドメインをお持ちなら追加費用はかかりません）。

## 開発者の方へ

技術スタック: **Next.js 16 (App Router) / React 19 / TypeScript / Tailwind CSS v4 /
Clerk / Neon Postgres**

```bash
npm install
cp .env.example .env.local   # DATABASE_URL と Clerk の鍵を入れる
npm run dev
```

```bash
npm run build       # 本番ビルド（環境変数なしでも通ること）
npm run typecheck   # 型検査
```

- 設計の全体像と判断の理由 → **[DESIGN.md](DESIGN.md)**
- 作業するときの決まり → **[AGENTS.md](AGENTS.md)**

### 設計上の要点

- **環境変数が無くてもビルドと起動が成功する。** 主催者が「先にデプロイ、あとから
  設定」できるようにするため。壊すと `/setup` すら開けなくなる
- **マイグレーション CLI を使わない。** スキーマは初回アクセス時に自動適用
- **在庫とチケットは条件付きの 1 本の SQL で更新する。** 同時操作で二重に
  動かないようにするため
- **iOS / Android のどちらにも依存しない。** QR 読み取りは両 OS で動く ZXing
