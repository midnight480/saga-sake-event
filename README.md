# 佐賀 蔵めぐり

佐賀の酒蔵が集まる**合同試飲イベント**の、受付・在庫・チケットを 1 つにまとめた
Web サービスです。

**主催者・酒蔵・参加者の 3 者が、同じ画面の情報を共有します。**
どこか 1 台で操作すると、ほかの画面が数秒で追いつきます。

- 参加者は**ブースの前でスマホから注文**し、できあがりを画面で知る
- 酒蔵は**持ち込んだ酒を自分で登録**し、注文を順に片付ける
- 主催者は**在庫・混雑・遅延をひと目で把握**し、券が切れたらその場で増やす

アプリのインストールは要りません。**URL を開くだけ**で、iPhone でも Android でも
同じように使えます。

---

## 主催者の方へ ─ 公開するまで

**プログラミングの知識は要りません。** かかる時間はおよそ **15 分**、費用は
**無料の範囲で始められます**。

入口が 2 つあります。**ほとんどの方は A です。**

### A. このリポジトリを配布された方（通常はこちら）

主催を引き受けて、URL や案内を受け取った方はこちらです。
リポジトリを自分のアカウントに複製してから公開します。

[![Vercel でデプロイ](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https%3A%2F%2Fgithub.com%2Fmidnight480%2Fsaga-sake-event&project-name=saga-sake-event&repository-name=saga-sake-event)

1. 上のボタンを押す
2. GitHub でログイン（無料。持っていなければその場で作れます）
3. リポジトリ名はそのままで **「Create」**
4. 次の画面で、下の表のとおりになっているか確かめてから **「Deploy」**

### B. このリポジトリを自分で持っている方

`midnight480/saga-sake-event` の所有者・共同編集者、または動作確認のために
自分のアカウントで試す方はこちらです。

**A の Deploy ボタンは使えません。** あのボタンは「リポジトリを自分のアカウントに
複製する」ためのもので、すでに同じ名前のリポジトリがあると
`A repository named "saga-sake-event" already exists.` で止まります。
ここで名前を変えて進めると**別のコピー**ができ、元のリポジトリを更新しても
サイトに反映されなくなります。

1. **<https://vercel.com/new>** を開く
2. 「Import Git Repository」の一覧から **`saga-sake-event`** を選び **「Import」**
   - 一覧に出ないときは検索欄に `saga-sake` と入力
   - それでも出ないときは一覧の下の **「Adjust GitHub App Permissions」** から
     `saga-sake-event` へのアクセスを許可する
3. 次の画面で、下の表のとおりになっているか**必ず確かめてから** **「Deploy」**

---

### ⚠️ Deploy を押す前に、この 3 つを確認してください

似た名前のリポジトリがあると、**違うプロジェクトを公開してしまいます。**
Vercel の画面で、次の 3 か所が合っているか見てください。

| 画面の項目 | 正しい値 | 違っていたら |
| --- | --- | --- |
| **Repository** | `midnight480/saga-sake-event` | 別のリポジトリです。戻ってやり直してください |
| **Git Branch** | `main` | `main` 以外を選ぶと、未完成の内容が公開されます |
| **Application Preset** | `Next.js` | `Other` と出ていたら、**違うリポジトリを見ています** |

> **Application Preset がいちばん分かりやすい目印です。**
> 正しいリポジトリなら Vercel が自動で `Next.js` を検出します。
> `Other` のままなら、リポジトリ名を読み違えていないか確かめてください
> （例: `saga-event-space` は別のプロジェクトです）。

### Environment Variables に `5 Detected` と出たら

そのまま進んで構いません。Vercel が `.env.example` を読んで変数名を拾っただけで、
**値はすべて空のままにしてください**（値が空の変数は作られません）。

このアプリは環境変数が未設定でも公開でき、開くと「はじめの設定」画面が
足りないものを案内します。値を手で入れる必要はありません。

### 公開したあとの続き

```
5. できあがった URL を開くと「はじめの設定」画面が出ます
6. 画面に書いてある 2 つの設定（Neon と Clerk）を、案内どおりに追加する
7. 「主催者としてはじめる」を押して、ご自身のメールアドレスで登録
```

**6 番の設定も、Vercel の画面でボタンを押すだけです。**
むずかしい文字列をコピーして貼り付ける作業はありません。

> 手順の詳細（押す場所を 1 つずつ）→ **[docs/デプロイ手順.md](docs/デプロイ手順.md)**
> うまくいかないとき → **[docs/よくあるトラブル.md](docs/よくあるトラブル.md)**
> 当日の進め方 → **[docs/当日の運営手順.md](docs/当日の運営手順.md)**

### 公開したあとの自動更新

Vercel は **`main` ブランチ**を見ています。`main` に push するたび、
本番サイトが自動で作り直されます（1〜2 分）。

ほかのブランチに push した場合は、本番とは別の「確認用 URL」が作られます。
本番は変わりません。

### 公開したあと、最初にやること

1. **自分でログインする。** 最初にログインした人が主催者になります。
   ほかの人に先に開かれないよう、URL を配る前に済ませてください。
2. **イベント設定**で日付と時刻を入れる
3. **蔵アカウント**で出展する酒蔵を登録し、印刷して各蔵に渡す
4. **チケットQR**で当日券を発行し、印刷して受付に置く

## かかる費用

| | 無料の範囲 | 超えたら |
| --- | --- | --- |
| Vercel（サイトの置き場所） | 個人利用は無料 | 規模が大きくなったら有料プラン |
| Neon（データの保存） | 無料プランで十分 | 数百人規模のイベントなら無料枠で足ります |
| Clerk（ログイン） | 月 10,000 人まで無料 | 来場者がそれ以上なら有料 |

一般的な規模（来場者 数百人・出展 30 蔵）なら、**すべて無料枠に収まります**。

## 開発者の方へ

技術スタック: **Next.js 16 (App Router) / React 19 / TypeScript / Tailwind CSS v4 /
Clerk / Neon Postgres**

```bash
npm install
cp .env.example .env.local   # DATABASE_URL と Clerk の鍵を入れる
npm run dev
```

```bash
npm run build       # 本番ビルド（環境変数なしでも通ること）
npm run typecheck   # 型検査
```

- 設計の全体像と判断の理由 → **[DESIGN.md](DESIGN.md)**
- 作業するときの決まり → **[AGENTS.md](AGENTS.md)**

### 設計上の要点

- **環境変数が無くてもビルドと起動が成功する。** 主催者が「先にデプロイ、あとから
  設定」できるようにするため。壊すと `/setup` すら開けなくなる
- **マイグレーション CLI を使わない。** スキーマは初回アクセス時に自動適用
- **在庫とチケットは条件付きの 1 本の SQL で更新する。** 同時操作で二重に
  動かないようにするため
- **iOS / Android のどちらにも依存しない。** QR 読み取りは両 OS で動く ZXing
