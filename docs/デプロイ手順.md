# デプロイ手順（主催者向け）

プログラミングの知識は要りません。**押す場所を 1 つずつ書いています。**
上から順にそのまま進めてください。全部で **15 分ほど**です。

用意するもの:

- パソコン（スマホでもできますが、パソコンの方が楽です）
- メールアドレス 1 つ

---

## 全体の流れ

```
STEP 1  GitHub のアカウントを作る（持っていれば飛ばす）
STEP 2  サイトを作る（Vercel に取り込む）
STEP 3  データの保存場所（Neon）を追加する
STEP 4  ログインの仕組み（Clerk）を追加する
STEP 5  みんなが開けるようにする  ← ここを飛ばすと誰も開けません
STEP 6  自分が主催者になる
STEP 7  イベントの中身を入れる
```

STEP 3 と 4 で出てくる**「鍵」のような文字列は、自動で入ります。**
コピーして貼り付ける作業はありません。

---

## STEP 1 ─ GitHub のアカウントを作る

すでに持っている方は **STEP 2 へ**。

1. <https://github.com/signup> を開く
2. メールアドレス、パスワード、ユーザー名を入れる
3. 届いたメールの数字を入れて登録を完了する

> **GitHub とは**: プログラムの置き場所です。ここに置いたものを、次の STEP で
> インターネットに公開します。無料です。

---

## STEP 2 ─ サイトを作る

**入口が 2 つあります。ほとんどの方は A です。**

### A. このリポジトリを配布された方（通常はこちら）

主催を引き受けて、案内を受け取った方はこちらです。
リポジトリを自分のアカウントに複製してから公開します。

1. [README のいちばん上にある **「Deploy with Vercel」** のボタン](../README.md)を押す
2. Vercel のログイン画面が出たら **「Continue with GitHub」** を押す
   （STEP 1 で作ったアカウントでログインします）
3. **「Repository Name」に、あなたのイベントの名前を入れる**

   ⭐ **ここで入れた名前が、そのまま公開される URL になります。**

   ```
   kuramenguri-saga-2026  と入れると
          ↓
   https://kuramenguri-saga-2026.vercel.app  が自分のサイトの URL になります
   ```

   短い URL は**世界中で早い者勝ち**です。初期値の `saga-sake-event` のまま
   進めると、すでに誰かが使っていた場合この短い URL はもらえません
   （アカウント名入りの長い URL は必ずもらえるので、公開自体はできます）。

   **地域名や年を入れて、自分だけの名前にしてください。**

   | | 例 |
   | --- | --- |
   | ◎ おすすめ | `kuramenguri-saga-2026` / `saga-sake-2026aki` / `sagakura-spring` |
   | △ 被りやすい | `saga-sake-event`（初期値のまま） / `sake-event` |

   使える文字は **小文字の英数字とハイフン（-）** です。日本語は使えません。

4. **「Create」** を押す
5. **STEP 2-3（下記）の確認**をしてから **「Deploy」** を押す

### B. このリポジトリを自分で持っている方

`midnight480/saga-sake-event` の所有者・共同編集者、または動作確認のために
自分のアカウントで試す方はこちらです。

**A の Deploy ボタンは使えません。** あのボタンは「リポジトリを自分の
アカウントに複製する」ためのもので、すでに同じ名前のリポジトリがあると
次のように止まります。

```
A repository named "saga-sake-event" already exists. Choose a different name.
```

ここで名前を変えて進めると、**別のコピー**ができてしまい、元のリポジトリを
更新してもサイトに反映されなくなります。名前は変えずに、次の手順に進んでください。

1. **<https://vercel.com/new>** を開く
2. Vercel のログイン画面が出たら **「Continue with GitHub」** を押す
3. **「Import Git Repository」** の一覧から **`saga-sake-event`** を探して
   **「Import」** を押す
   - 一覧に出ないときは、検索欄に `saga-sake` と入力してください
   - それでも出ないときは、一覧の下にある
     **「Adjust GitHub App Permissions」** を押して、
     `saga-sake-event` へのアクセスを許可してください
4. **STEP 2-3（下記）の確認**をしてから **「Deploy」** を押す

---

## STEP 2-3 ─ Deploy を押す前の確認（大事）

似た名前のリポジトリがあると、**違うプロジェクトを公開してしまいます。**
画面の次の 3 か所を見てください。

| 画面の項目 | 正しい値 |
| --- | --- |
| **Repository**（Importing from GitHub） | `midnight480/saga-sake-event` |
| **Git Branch** | `main` |
| **Application Preset** | `Next.js` |

**いちばん分かりやすい目印は Application Preset です。**

- `Next.js` と出ている → **正しいリポジトリです。**そのまま進んでください
- `Other` と出ている → **違うリポジトリを見ています。**
  前の画面に戻って選び直してください

> よくある間違い: `saga-event-space` という名前のよく似たリポジトリがあります。
> これは別のプロジェクトです。**`saga-sake-event`**（`sake` が入っている方）が
> 正しいリポジトリです。

### Environment Variables ─ 2 つだけ入れてください

`Environment Variables` の欄を開くと、いくつかの名前が出てきます
（このリポジトリの `.env.example` を Vercel が読んだものです）。

**入力するのは 1 つだけ**です。

| 欄 | どうするか |
| --- | --- |
| **`ORGANIZER_EMAILS`** | **ご自身のメールアドレスを入れてください**（下記参照） |
| `DATABASE_URL` | **空のまま**（STEP 3 で Neon が自動で入れます） |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | **空のまま**（STEP 4 で Clerk が自動で入れます） |
| `CLERK_SECRET_KEY` | **空のまま**（同上） |

空のままにしたものは作られません。手で値を入れる必要はありません。

> #### ⭐ `ORGANIZER_EMAILS` は必ず入れてください
>
> **入れないと、「最初にログインした人」が自動で主催者になります。**
> URL を先に誰かに開かれると、その人が運営権限を持ってしまいます。
>
> ここでご自身のメールアドレスを入れておけば、**その人だけが主催者**に
> なります。複数の運営メンバーがいる場合はカンマ区切りです。
>
> ```
> ORGANIZER_EMAILS = anata@example.com
> ORGANIZER_EMAILS = anata@example.com,staff@example.com
> ```
>
> あとから STEP 5 以降で追加することもできますが、そのときは
> Settings → Environment Variables に入れたうえで、再デプロイが必要です。

---

## STEP 2-4 ─ Deploy して待つ

1. **「Deploy」** を押す
2. **2〜3 分待つ。** 花火のアニメーションが出たら完成です
3. **「Continue to Dashboard」** を押す

この時点で、サイトはもうインターネット上にあります。
画面上部に `〇〇〇.vercel.app` という URL が出ているので、**これを開いてみてください。**

→ **「はじめの設定」** という画面が出ます。ここに「あと 2 か所」と書かれています。
次の STEP でその 2 つを埋めます。

> **Vercel とは**: サイトを公開しておく場所です。個人利用は無料です。

> **これ以降の更新について**: Vercel は **`main` ブランチ**を見ています。
> `main` に変更が入るたび、サイトは自動で作り直されます（1〜2 分）。

## STEP 3 ─ データの保存場所を追加する（Neon）

酒蔵・銘柄・チケットなどの情報をしまう場所です。

1. Vercel の画面に戻り、プロジェクト **`saga-sake-event`** を開く
2. **画面の左にならんでいるメニュー**から **「Storage」** を押す

   > ⚠️ **画面の上ではなく、左です。** Vercel のプロジェクト画面は、
   > 左側に Overview / Deployments / … / Integrations / Storage / Settings と
   > 縦にならんでいます。「Storage」はその下のほうにあります。
   >
   > ```
   > saga-sake-event
   >  ├ Overview
   >  ├ Deployments
   >  │   …
   >  ├ Integrations   ← STEP 4 で使います
   >  ├ Storage        ← いま押すのはここ
   >  ├ Flags
   >  │   …
   >  └ Settings
   > ```

3. **「Create Database」**（または **「Connect Database」**）を押す
4. 一覧から **「Neon」** を選ぶ（Serverless Postgres と書かれています）
5. プランは **「Free」** のまま。**「Continue」** を押す
6. データベースの名前はそのままでよい。**「Create」** を押す
7. 作成後、**このプロジェクトに接続する**画面が出たら **「Connect」** を押す
   - 出てこなかった場合: できた Neon を開いて **「Projects」** タブ →
     **「Connect Project」** → `saga-sake-event` を選ぶ

**これで接続先の情報は自動で入ります。** 何も書き写す必要はありません。

Vercel はこのあと自動でサイトを作り直します（1〜2 分）。

> **Neon とは**: データをしまうデータベースです。無料プランで、
> 数百人規模のイベントには十分です。

---

## STEP 4 ─ ログインの仕組みを追加する（Clerk）

参加者・酒蔵・主催者のログインを担当します。

1. Vercel の画面で、プロジェクト **`saga-sake-event`** を開く
2. **画面の左にならんでいるメニュー**から **「Integrations」** を押す
   （STEP 3 の「Storage」のすぐ上にあります）

   > 見つからないときは <https://vercel.com/marketplace/clerk> を直接開いても
   > 構いません。

3. **「Browse Marketplace」** から **`Clerk`** を探して選ぶ
4. **「Install」** を押す
5. プランは **「Free」** のまま進む
6. 接続するプロジェクトとして **`saga-sake-event`** を選ぶ
7. **「Install」/「Continue」** を押して完了

**これで鍵は自動で入ります。**

### 4-2 ─ 酒蔵のログインを使えるようにする（大事）

酒蔵には `kura-001` のような **ID とパスワード**を配ります。
この方式を使うため、Clerk 側で 1 か所だけ設定を入れてください。

1. <https://dashboard.clerk.com> を開く（STEP 4 で作られたアカウントで入れます）
2. 左のメニューから **「User & Authentication」** → **「Email, Phone, Username」**
3. **「Username」** のスイッチを **オン** にする
4. **「Password」** のスイッチが **オン** になっていることを確かめる

> ここを設定しないと、酒蔵のアカウントを発行しようとしたときに
> 「ログインアカウントを作れませんでした」と出ます。

---

## STEP 5 ─ みんなが開けるようにする（とても大事）

**ここを飛ばすと、URL を配っても来場者は誰ひとり開けません。**
画面には Vercel のログインを求められ、「自分は入れるのに、他の人は入れない」
という一番気づきにくい状態になります。

Vercel は新しく作ったサイトに、既定で **「Vercel Authentication」** という
鍵をかけます。中身を確認するまで外部に見せないための機能ですが、
このアプリは来場者に開いてもらうものなので、外す必要があります。

### 5-1 ─ 鍵を外す

1. Vercel でプロジェクトを開く
2. **画面の左のメニューの「Settings」**を押す
3. Settings の中の一覧から **「Deployment Protection」** を選ぶ

   > 左のメニューの直下ではなく、**Settings を開いた中**にあります。
   >
   > ```
   > 左メニュー          Settings を開いた中
   >  ├ Overview           General
   >  ├ Deployments        Domains
   >  │   …                Environment Variables
   >  ├ Storage            Git
   >  └ Settings  ──────▶  Deployment Protection   ← ここ
   >                       Functions
   >                       …
   > ```

4. **「Vercel Authentication」** を **Disabled** にする
5. **「Save」** を押す

### 5-2 ─ 開けることを確かめる

**必ず、ふだん使っていないブラウザか、スマホのシークレットモードで確認してください。**
自分のパソコンは Vercel にログイン済みなので、鍵がかかっていても開けてしまい、
気づけません。

```
https://〇〇〇.vercel.app/setup
```

「はじめの設定」の画面が出れば成功です。
Vercel のログイン画面が出たら、5-1 がまだ効いていません。

### 5-3 ─ それでも「404 The deployment could not be found」と出るとき

ドメインがデプロイに結びついていません。**作り直し（Redeploy）では直らない**
ことがあります。そのときは **昇格（Promote）** してください。

1. 左のメニューの **「Deployments」** を押す
2. いちばん上の行の右端 **「⋯」** を押す
3. **「Promote to Production」** を選ぶ

1 分ほどで開けるようになります。

> この状態になるのは、サイトを作ったあとにドメインを足したときです。
> ドメインは次の「昇格」のタイミングで結びつけられます。

---

## STEP 6 ─ 自分が主催者になる

**この操作は、URL を人に配る前に済ませてください。**
最初にログインした人が主催者になるためです。

1. `〇〇〇.vercel.app` を開く
2. 「はじめの設定」の項目がすべて緑色（✓）になっているか確認する
   - まだ赤や金色のものがあれば、その項目に書かれた手順を進める
   - 設定したのに変わらないときは、**画面を再読み込み**する
3. **「主催者としてはじめる」** を押す
4. ご自身のメールアドレスを入れる
5. 届いたメールの数字を入れる

→ 運営の画面（ダッシュボード）が開きます。**これで準備完了です。**

> **もし先にほかの人がログインしてしまったら**: Vercel の
> 「Settings」→「Environment Variables」で `ORGANIZER_EMAILS` という名前で
> ご自身のメールアドレスを登録し、作り直してください。
> （[よくあるトラブル](よくあるトラブル.md)に詳しく書いています）

---

## STEP 7 ─ イベントの中身を入れる

運営の画面の下のタブから、順に進めます。

### 7-1 イベント設定

- **開催日**・**開始時刻**・**終了時刻** を入れる
- **参加酒蔵数** を出展予定の蔵数にする
- ここではまだ「イベントを開始する」を押さない（当日押します）

### 7-2 蔵アカウント

出展する酒蔵を 1 つずつ登録します。

- **酒蔵名** を入れて、**所在地** を選び、**「登録してID・パスワードを発行」**
- 発行された **蔵ID とパスワードが表示されます**
  - **この画面を閉じると、もう表示できません**
  - 「コピーする」を押して控えるか、書き写してください
  - 見失っても「パスワードを再発行する」でいつでも作り直せます
- 全蔵の登録が終わったら、いちばん下の
  **「全蔵のID・パスワードを作り直して印刷する」** で配布用の紙が作れます
  - ただし**押すと、前に配ったパスワードは使えなくなります**。
    まだ配っていないなら、こちらで一括印刷するのが楽です

### 7-3 チケットQR

- **「当日券 10枚」** の **「＋50枚 発行」** を必要な枚数分押す
  （1 枚の QR で 10 枚分のチケットになります。100 人分なら 100 枚発行）
- **「印刷用ページ」** を押すと QR の台紙が出ます。**印刷して受付に置いてください**
- **1 枚ごとに違うコードです。** コピーしても増えません

## できあがったもの

| 誰が | どこを開くか |
| --- | --- |
| 主催者 | `〇〇〇.vercel.app` → 自動で運営画面へ |
| 酒蔵 | `〇〇〇.vercel.app` → 配った蔵ID とパスワードでログイン |

## ⚠️ 来場者が 100 人を超える場合

**この状態のままでは、登録できる人数が合計 100 人までです。**
ログインを担当する Clerk が「開発モード」で動いているためです。

しかも**開発モードで登録した人は、あとから引き継げません。**
当日になって上限に達してからでは手遅れです。

100 人を超える見込みがあるなら、イベントの前に
**[独自ドメインで本番運用する](独自ドメインで本番運用する.md)** を済ませてください。
すでにドメインをお持ちなら、追加費用なしで対応できます。
