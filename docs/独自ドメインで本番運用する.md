# 独自ドメインで本番運用する

[デプロイ手順](デプロイ手順.md)を終えると、`〇〇〇.vercel.app` でサイトが動きます。
**小規模な下見や練習ならこのままで十分です。**

ただし、**来場者が 100 人を超える本番のイベントでは、この文書の作業が必要です。**

---

## なぜ必要か ─ 100 人の壁

ログインを担当する Clerk には、2 つの状態があります。
`〇〇〇.vercel.app` のままだと、左の「開発モード」でしか使えません。

| | 開発モード（初期状態） | 本番モード |
| --- | --- | --- |
| 登録できる人数 | **合計 100 人まで** | 10,000 人まで無料 |
| 必要なもの | なし | **自分のドメイン** |
| `〇〇〇.vercel.app` | 使える | **使えない** |
| 画面の表示 | 下に「Development mode」と出る | 出ない |

100 人は**主催者・酒蔵・参加者の合計**です。出展 30 蔵なら、参加者は 69 人で
打ち止めになります。

さらに厄介なのが次の点です。

> **開発モードで登録した人は、本番モードへ引き継げません。**

つまり「当日 100 人に達してから本番へ切り替える」ができません。
**イベントの前に切り替えておく必要があります。**

---

## 用意するもの

**自分で持っているドメインが 1 つ。** 新しく買う必要はありません。

酒造組合や事務局がすでにドメインを持っていることが多いので、その一部を
借りるのがいちばん簡単です。

```
すでに持っているドメイン    example.or.jp
                              ↓
このアプリに使うサブドメイン  kuramenguri.example.or.jp
```

サブドメインなら、**今あるホームページには一切影響しません。**
追加の費用もかかりません。

DNS がどこにあっても構いません（Cloudflare、Route 53、お名前.com、
さくらインターネット、Vercel など）。

---

## 手順

### STEP A ─ Vercel にドメインを登録する

1. Vercel でプロジェクトを開く
2. 左のメニューの **「Settings」** → **「Domains」**
3. 使いたいサブドメイン（例: `kuramenguri.example.or.jp`）を入れて **「Add」**
4. **画面に表示される設定値を控える**（`CNAME` と、その行き先）

### STEP B ─ DNS に登録する

ドメインを管理している画面で、STEP A で表示された値を登録します。

| 種類 | 名前 | 行き先 |
| --- | --- | --- |
| CNAME | `kuramenguri` | Vercel の画面に出た値 |

> #### ⚠️ Cloudflare を使っている場合
>
> **オレンジの雲のアイコンを、灰色（DNS only）にしてください。**
>
> オレンジのままだと Cloudflare が通信を中継してしまい、このあとの Clerk の
> 確認が通りません。レコードを追加したあと、雲のアイコンをクリックすると
> 灰色に切り替わります。
>
> このあと STEP D で追加するレコードも、**すべて灰色**にしてください。

> #### Route 53 / お名前.com / さくら の場合
>
> 中継の仕組みが無いので、そのまま CNAME を登録するだけで構いません。

数分〜十数分で Vercel の画面に **Valid Configuration** と出ます。

### STEP C ─ Clerk を本番モードにする

1. <https://dashboard.clerk.com> を開く
2. 画面の左上、**「Development」** と書かれた部分を押す
3. **「Create production instance」** を選ぶ
4. 開発モードの設定をコピーするか聞かれたら、**コピーする**を選ぶ
5. ドメインを聞かれたら、STEP A で登録したものを入れる
   （例: `kuramenguri.example.or.jp`）

### STEP D ─ Clerk が指示する DNS を登録する

Clerk の **「Domains」** の画面に、登録すべきレコードが数件表示されます
（`clerk.` `accounts.` `clkmail.` などで始まるもの）。

**これを DNS に登録してください。Cloudflare なら、すべて灰色（DNS only）です。**

すべて緑のチェックになれば完了です。反映まで数分〜1 時間ほどかかります。

### STEP E ─ 本番の鍵を Vercel に入れる

1. Clerk の **「API Keys」** を開く（本番モードになっていることを確認）
2. 2 つの値をコピーする
   - `pk_live_` で始まるもの（Publishable key）
   - `sk_live_` で始まるもの（Secret key）
3. Vercel の **「Settings」** → **「Environment Variables」** で、
   **すでにある空の欄**に貼り付ける

| 変数名 | 入れる値 |
| --- | --- |
| `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY` | `pk_live_...` |
| `CLERK_SECRET_KEY` | `sk_live_...` |

> この名前は、Clerk 連携が自動で入れた名前（`AUTHENTICATION_` で始まるもの）
> **より優先して読まれます**。連携が入れたものは消さなくて構いません。

### STEP F ─ ⭐ 主催者のメールアドレスを必ず入れる

**ここを飛ばすと、運営画面に入れなくなります。**

開発モードと本番モードでは、同じメールアドレスでも**別人として扱われます**
（内部の ID が変わるため）。アプリは主催者をその ID で覚えているので、
切り替えた瞬間にあなたは主催者ではなくなります。

同じ画面で、次の変数にご自身のメールアドレスを入れてください。

| 変数名 | 入れる値 |
| --- | --- |
| `ORGANIZER_EMAILS` | ご自身のメールアドレス（複数はカンマ区切り） |

メールアドレスで判定されるようになるので、ID が変わっても主催者のままです。

### STEP G ─ 作り直して確かめる

1. 左のメニューの **「Deployments」** → いちばん上の **「⋯」** →
   **「Redeploy」**
2. 2〜3 分待つ
3. `https://kuramenguri.example.or.jp/setup` を開く

**ログイン画面の下に「Development mode」が出なくなっていれば成功です。**

### STEP H ─ Username をもう一度有効にする

本番モードは別の設定を持っているので、**開発モードでの設定は引き継がれません。**

1. Clerk で本番モードになっていることを確認
2. **「User & Authentication」** → **「Email, Phone, Username」**
3. **「Username」** をオン、**「Password」** がオンであることを確認

これを忘れると、酒蔵のアカウントを発行するときに失敗します。

---

## 切り替えたあとに起きること

- **開発モードで作ったアカウントは、すべて使えなくなります。**
  練習で登録した蔵アカウントは、本番モードで発行し直してください
- **登録済みの酒蔵・銘柄・チケットは残ります**（これらは Clerk ではなく
  データベースにあるため）。ただし蔵のログイン情報だけは作り直しが必要です
- `〇〇〇.vercel.app` も引き続き開けますが、**ログインは新しいドメインでしか
  動きません。** 案内は独自ドメインのほうを配ってください

| | |
| --- | --- |
| すでにドメインを持っている場合 | **追加費用なし**（サブドメインは無料） |
| 新しく取る場合 | 年 1,500 円ほど（Vercel の Domains からも買えます） |
| Clerk 本番モード | 10,000 人まで無料 |
